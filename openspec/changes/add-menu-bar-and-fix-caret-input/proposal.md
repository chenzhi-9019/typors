# Proposal

## Why

typors 目前没有菜单栏，所有命令只能靠快捷键或命令行完成；同时“直接启动、不读取文件”的空文档没有可命中的文本块，光标既不显示也无法通过点击定位，输入/IME 在这种状态下不可靠。光标在换行、空行、行边界和对象边界上还会出现位置偏移、停在上一行、粗细/行高异常和残影。用户需要的是 Typora 式的可见命令入口，以及任何文档状态下都可信的光标与输入。

## What Changes

- 新增 GPUI 自绘菜单栏，固定在编辑区上方，包含 `文件(F)`、`编辑(E)`、`段落(P)`、`格式(O)`、`视图(V)`、`主题(T)`、`帮助(H)` 七个入口，外观与信息层级参考截图。
- 菜单支持鼠标点击、`Alt+F/E/...` 助记键、左右切换、上下选择、Enter 执行、Esc/点击外部关闭；关闭后焦点回到编辑器。
- 文件菜单提供新建空白文档、打开、保存、另存为、退出；编辑/段落/格式菜单复用现有编辑能力（撤销重做、剪切复制粘贴、标题/列表/引用/代码块、粗体/斜体/删除线/行内代码/公式/链接）；视图与主题菜单提供当前已支持或本次新增的开关。
- 无文件启动（直接运行 `typors`）进入一个明确可编辑的空文档：文档至少有一个文本块，焦点/点击都能把光标放到 0 位置，输入、回车和 IME 立即生效。
- 修复光标几何：行首/行尾、软换行、连续空行、末尾空行、标题/代码/引用/对象边界都按所在行框定位；光标宽度使用逻辑像素、高度使用该行行高；不在旧位置留下残影，也不因菜单/焦点切换错误消失。
- 为菜单、空文档输入和光标几何增加可回归的探针与测试，覆盖空文档、连续回车、行首/行尾、对象相邻、缩放与失焦/重新聚焦。

## Capabilities

### New Capabilities

- `editor/app-menu-bar`: 菜单栏的结构、交互、命令分发、焦点与主题行为。
- `editor/caret-and-blank-document`: 空文档的可编辑性，以及光标在各类行/边界/对象上的几何与可见性。

## Impact

- `crates/typors-runtime/src/app.rs`：窗口根视图从 `MarkdownView` 改为带菜单栏的 editor shell；文件新建/打开/保存路径与窗口标题。
- `crates/typors-editor/src/view.rs`：根视图布局（菜单行 + 滚动页面）、焦点恢复、空文档初始化与命中测试。
- `crates/typors-render/src/render.rs`：`caret_x`/`caret_bounds` 的行框与边界规则。
- `crates/typors-core/src/doc.rs`：空文本至少一个可编辑块，`block_at_src(0)` 与编辑后重解析保持一致。
- `crates/typors-probes`：新增菜单/空文档/光标回归探针。
- 不改变安装器、Mermaid/LaTeX/图片渲染管线；菜单打开时不触发文档重排。
